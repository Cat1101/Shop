# AGENTS.md

## Работа с Git

- Работай в отдельном Git worktree и отдельной ветке для задачи. Перед правками проверь `git status --short --branch`, текущий worktree и remote `origin`.
- Делай небольшие тематические коммиты по завершённым этапам. Перед каждым коммитом проверь staged diff и выполни проверки, относящиеся к этапу.
- После каждого готового коммита сразу отправляй текущую ветку в `origin`. При первом push задай upstream через `git push -u origin <branch>`. Продолжай работу после проверки результата push.
- Открывай pull request для ревью, когда ветка готова. Сохраняй пользовательские изменения и чужую историю Git.

## Устройство проекта

- `apps/web` содержит витрину Next.js с App Router. Доступ к API и сессии остаётся на сервере Next.js. Клиентские компоненты отвечают за интерактивность и корзину.
- `apps/api` содержит NestJS API. Группируй код по функциям магазина: каталог, аккаунты и заказы. HTTP-контроллеры проверяют входные данные, сервисы выполняют бизнес-операции.
- `apps/api/prisma` содержит схему и миграции PostgreSQL. Для доступа к базе используй Prisma. Добавляй миграцию к каждому изменению схемы и сохраняй историю применённых миграций.
- `compose.yaml` запускает локальные Next.js, NestJS, PostgreSQL и Mailpit. Включай в коммиты `package-lock.json` при изменении зависимостей. Реальные секреты и локальные `.env` оставляй вне Git.

## Проверки и данные

- Запуск: `docker compose up --build -d --wait`. Проверь `docker compose ps`, витрину на порту 3000 и `/api/health` на порту 3001.
- Для изменений аккаунта проверь письмо в Mailpit, подтверждение адреса и вход. Для изменений заказов проверь создание заказа, историю и изменение остатков.
- Для остановки используй `docker compose down`. Сохраняй том PostgreSQL и данные в нём.
- Храни суммы целыми числами в копейках. Рассчитывай цену заказа по данным базы, проверяй остатки и изменяй их в одной транзакции с созданием заказа.

## Стиль кода

- Пиши читаемый TypeScript в строгом режиме. Используй понятные имена, небольшие функции и явные типы на границах API.
- Если понадобится Python, соблюдай PEP 8: одна команда на строку, без точек с запятой, отступы 4 пробела, пробелы вокруг операторов, понятные имена и небольшие функции. Не сокращай код ради компактности.
